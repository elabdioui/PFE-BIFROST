\chapter{Conception et Plan de Développement}
\label{chap:conception_developpement}

\section*{Introduction}

La conception technique constitue la pierre angulaire de tout projet de développement logiciel. Pour le système JLHUBSECURITY, une approche méthodique basée sur les meilleures pratiques du génie logiciel a été adoptée afin de garantir la robustesse, la scalabilité et la maintenabilité de la solution. Ce chapitre présente l'architecture technique choisie, les technologies utilisées, la modélisation UML du système ainsi que les bonnes pratiques de développement mises en œuvre.

\section{Architecture Générale du Système}

\subsection{Vue d'Ensemble}

L'architecture de JLHUBSECURITY s'appuie sur une approche modulaire et orientée services, structurée selon le pattern MVC (Modèle-Vue-Contrôleur). Cette architecture garantit une séparation claire des responsabilités, facilite la maintenance et permet une évolutivité optimale du système.

\begin{figure}[H]
\centering
\includegraphics[width=1.0\textwidth]{image/layered.png}
\caption{Architecture générale du système JLHUBSECURITY}
\label{fig:architecture_generale}
\end{figure}

L'architecture se compose de trois couches principales interconnectées via des API REST sécurisées, permettant une communication fluide entre les différents composants du système.

\subsection{Architecture Multi-Tiers}

\subsubsection{Couche de Présentation (Frontend)}
La couche présentation est développée avec Vue.js et s'articule autour de composants modulaires et réutilisables. Elle assure l'interface utilisateur et la logique d'affichage, intégrant PrimeVue pour les composants UI et Highcharts pour la visualisation de données.

\subsubsection{Couche d'Application (Backend)}
La couche application, développée avec Laravel, contient la logique métier, la gestion des API REST et l'orchestration des services. Elle assure la sécurité, la validation des données et la coordination entre les différents modules.

\subsubsection{Couche de Données}
Cette couche gère la persistance des données via MySQL, incluant la gestion des transactions, l'optimisation des requêtes et la cohérence des informations stockées.

\subsubsection{Architecture Globale}

\begin{figure}[H]
\centering
\includegraphics[width=1\textwidth]{image/class totale.png}
\caption{Architecture Globale - Relations entre tous les Modules}
\label{fig:diagramme_classes_global}

L'architecture globale (Figure \ref{fig:diagramme_classes_global}) présente une vue d'ensemble des interactions entre tous les modules du système. Cette représentation met en évidence plusieurs aspects architecturaux fondamentaux :

\paragraph{Centralité des entités core :} Les classes \texttt{User}, \texttt{Site} et \texttt{DeliveryValidationCircuits} constituent le cœur du système, servant de point de convergence pour tous les modules métier.

\paragraph{Modularité et extensibilité :} Chaque type de demande (\texttt{DeliveryRequest}, \texttt{AccessRequest}, \texttt{MaterialRequest}) maintient sa spécificité tout en partageant une base commune, facilitant l'ajout de nouveaux modules.

\paragraph{Gestion multi-sites :} L'architecture prend en compte les particularités de chaque site OCP, avec des restrictions spécifiques pour Safi et Phosboucraa, tout en maintenant un accès complet pour les autres sites.

\paragraph{Workflow paramétrable :} Le système de circuits de validation permet une adaptation flexible des processus selon le type de demande et les spécificités du site, garantissant l'adaptabilité aux évolutions des besoins métier.

Cette modélisation en classes constitue la base solide sur laquelle repose l'ensemble de notre système, assurant à la fois la robustesse, la maintenabilité et l'évolutivité de la solution développée.

\section{Bonnes Pratiques de Développement}

\subsection{Architecture Modulaire}

\subsubsection{Principe de Séparation des Responsabilités}
L'application respecte le principe de responsabilité unique en organisant le code en modules spécialisés. Chaque module backend encapsule une fonctionnalité métier spécifique avec ses contrôleurs, services, et modèles associés. Cette approche facilite la maintenance, les tests, et l'évolution du système.

\subsubsection{Structure des Modules}
Chaque module suit une structure standardisée incluant les contrôleurs pour la gestion des requêtes HTTP, les services pour la logique métier complexe, les repositories pour l'accès aux données, les models pour la représentation des entités, et les tests unitaires pour la validation du comportement.

\subsection{Développement Frontend Modulaire}

\subsubsection{Composants Vue.js Réutilisables}
L'interface utilisateur est construite autour de composants Vue.js modulaires et réutilisables. Chaque composant encapsule sa logique, son template, et ses styles, favorisant la réutilisabilité et la maintenabilité. Les composants suivent une hiérarchie claire avec des composants de base (buttons, inputs), des composants métier (forms, tables), et des vues complètes.

\subsubsection{Gestion d'État Centralisée}
Vuex centralise la gestion de l'état de l'application avec des modules spécialisés pour chaque domaine fonctionnel. Cette approche garantit la cohérence des données, facilite le debugging, et améliore les performances en évitant les requêtes redondantes.

\subsection{Standards de Qualité}

\subsubsection{Conventions de Code}
Le projet respecte les standards PSR pour PHP et les guidelines Vue.js pour JavaScript. Les conventions incluent la nomenclature camelCase pour les variables, PascalCase pour les classes, des noms explicites pour les fonctions, et une documentation inline systématique.

\subsubsection{Tests et Validation}
Une couverture de tests minimale de 80\% est maintenue avec PHPUnit pour le backend et Jest pour le frontend. Les tests incluent des tests unitaires pour valider la logique métier, des tests d'intégration pour vérifier les interactions entre composants, et des tests fonctionnels pour valider les workflows utilisateur.

\subsection{Sécurité et Performance}

\subsubsection{Sécurisation des API}
Les API REST sont sécurisées avec un système d'authentification JWT, une validation stricte des données d'entrée, un système d'autorisation basé sur les rôles, et une protection contre les attaques courantes (CSRF, XSS, injection SQL).

\subsubsection{Optimisation des Performances}
Les performances sont optimisées via la mise en cache des requêtes fréquentes avec Redis, la compression des assets JavaScript et CSS, le lazy loading des composants Vue.js, et l'optimisation des requêtes SQL avec des index appropriés.

\section{Plan de Développement et Méthodologie}

\subsection{Approche Agile}

\subsubsection{Organisation en Sprints}
Le développement suit une méthodologie agile avec des sprints de 2 semaines. Chaque sprint inclut la planification des tâches, le développement avec daily standups, la revue des fonctionnalités développées, et la rétrospective pour l'amélioration continue.

\subsubsection{Collaboration Équipe}
La collaboration s'organise autour de rituels agiles incluant la planification de sprint pour définir les objectifs, les daily meetings pour le suivi quotidien, les démos pour valider les développements, et les rétrospectives pour identifier les axes d'amélioration.

\subsection{Pipeline CI/CD}

\subsubsection{Intégration Continue}
GitLab CI automatise le pipeline de développement avec l'exécution automatique des tests à chaque commit, l'analyse de qualité de code avec SonarQube, la construction des images Docker, et la génération de rapports de couverture.

\subsubsection{Déploiement Continu}
Le déploiement s'automatise via des environnements dédiés incluant le développement local avec Laragon, l'environnement de test pour la validation fonctionnelle, la préproduction pour les tests d'acceptation, et la production avec monitoring continu.
